# 小小修理铺：成长与章节设计

## 核心体验

接诊 → 读症状 → 安全准备 → 打开设备 → 观察 / 测量 → 形成证据 → 处理故障 → 复装 → 验证 → 知识小测 → 交付 → 赚维修费 → 购买工具 → 解锁更难的案例。

章节专注一类设备，关卡逐渐增加故障范围、判断难度和拆装精度。新工具先解释原理与用法；旧工具出现在新结构上时，补充场景教学。例如气吹从电脑鳍片迁移到风扇护网，再到键帽间隙；二合一拔取器从拔键帽升级为释放轴体卡扣。

## 已实现

- 电脑首关已加入默认的 3D 手动操作：正反向螺丝旋拧、两个独立卡扣、沿轴拔出、自由对位、旋转方向、主动推入与侧板复装。对位本身不会安装，错位和错误朝向会阻挡插入。
- 第二关共用手动螺丝与侧板拆装；先在模型中长按固定叶片，再用气吹逐处短按清理六处积灰。持续吹气、点按过快和偏离目标不会清理。
- 前两关手动模式中的机械步骤不能用“下一步”按钮完成；辅助教学是明确分开的可选入口。其余七关目前仍为辅助教学，尚未完成同等深度的手动拆装。
- 电脑、USB 风扇、机械键盘共 9 个可玩工单；三个设备的独立 3D 模型。
- 初始观察、螺丝刀、拆装；通过市场获得气吹、接线套件、润滑套装、万用表、拔取器与轴体套件。
- 工具所有权和操作前置条件检查；每次交付先通过设备验证与知识题。
- 首次发现零件的自动教学、按场景出现的工具教学、图鉴、笔记与维修日志。
- 章节和关卡依次解锁；维修费、经验、购置扣费、永久装备、重玩奖励去重与本机存档。
- 完整 12 类设备的可浏览章节地图；未实现内容明确标为“筹备中”。

## 经济设计

初始资金 ¥200；九张首通工单共提供 ¥1690；当前完整采购需要 ¥700，全部首通并采购后剩余 ¥1190。必要装备的购买价格与章节解锁时间经过预算测试，不会出现必须买工具但无可用资金的正常推进死局。

当前市场是“购买更专业的工具与替换套件”。套件永久保留、不重复消耗，避免早期原型被库存管理打断。后续可加入工具等级、精度、拆装效率和可选预算挑战，但不让付费或昂贵工具替代正确诊断。

## 后续应做的交互升级

1. 把已在前两关验证的手动交互扩展至其余工单和工具：SATA / FFC 插拔、清灰扫掠、拔键拔轴、表笔测试点。继续保留明确标注的辅助教学，不能把零件放到高亮位置就自动连接。
2. 工单逐渐减少提示：先跟做，再按症状选择检查路径，最终独立定位多故障。
3. 增加诊断仪实际界面、可检查测试点、可验证读数，避免仅凭任务按钮得到结论。
4. 增加零件兼容性、库存、返修与客户评价；用误诊与验证结果影响评分。
5. 新增手机和高风险章节前，先完成模型、设备规范与专业内容审校。真实市电、高压电容、锂电池、制冷剂、车辆安全和航空系统不直接照搬消费电子教程。

## 扩充一章的入口

在 `src/game.js` 添加设备零件、工单与工具条件；在 `src/tutorials.js` 添加场景教学；在 `src/Workbench.jsx` 添加设备模型及可点选分组；在 `src/roadmap.js` 将规划条目关联到实际可玩的 chapter id。用同一套维修状态机、市场与存档，不另建平行系统。
